## Условие и сценарий работы

Судну нужны буксир для входа и выхода, совместимый причал и один или несколько совместимых кранов. Для разгрузки требуется свободное место на складе, для погрузки - запас нужного груза. Вместимость и число ресурсов ограничены.

Диспетчер организует прибытие, вход, швартовку, грузовую операцию и выход. Он меняет общее состояние модели; остальные процессы выполняют задания и возвращают подтверждения.

| Участник | Что делает в своём процессе |
|---|---|
| Судно | Ожидает прибытия и подтверждает завершение своего жизненного цикла |
| Диспетчер | Ведёт модельное время, выбирает суда, назначает ресурсы, проверяет ограничения |
| Буксир | Выполняет вход или выход назначенного судна |
| Причал | Выполняет швартовку и освобождение, хранит номер своего судна |
| Кран | Участвует в обработке грузовой порции и подтверждает её завершение |
| Склад | Рассчитывает вывоз и подвоз груза с учётом запасов, резервов и вместимости |

Без наблюдателей работает `число судов + буксиров + причалов + кранов + 2` процессов, включая склад и сервер-диспетчер. Каждый наблюдатель - ещё один независимый процесс. Между приложениями используется только TCP; сервер не запускает клиентов. В `examples/manual.txt` это шесть процессов: диспетчер и пять участников.

### Жизненный цикл судна

```text
прибытие -> ожидание входа -> вход с буксиром -> ожидание причала
-> швартовка -> грузовые порции -> ожидание выхода -> выход с буксиром -> отход
```

- Если складская порция недоступна, судно ждёт без занятого причала. 
- При ожидании после частичной обработки оно сначала освобождает причал и переходит во внутреннюю зону ожидания, затем снова швартуется. Состояние DEPARTED не устанавливается. 
- Освобождение и повторная швартовка подтверждаются процессом причала. Их длительность задаёт moorTime. 
- Для пересечения границы порта при входе и окончательном выходе по-прежнему нужен буксир. 
- Вместимость внутренней зоны ожидания отдельно не моделируется.
- Если процесс существует, но перестал отвечать, моделирование может ожидать его ответ; для остановки используется Ctrl+C. Лимит модельного времени не гарантирует завершение такого ожидания.

### Стратегии и предотвращение взаимного ожидания

`strategy` определяет порядок рассмотрения:

- `0` - меньший номер судна;
- `1` - более раннее прибытие;
- `2` - меньший остаток груза.

При равенстве выбирается меньший номер. Начатая операция не вытесняется; неподходящий сейчас запрос может быть пропущен ради следующего.

`reservation` задаёт выделение ресурсов:

- `0` - по стадиям: входной буксир, затем причал, затем грузовая операция;
- `1` - входной буксир и причал резервируются согласованно. Если складская порция недоступна, вход с резервированием откладывается. При изменении склада во время входа неиспользованный резерв причала отменяется.

В обоих режимах полный набор кранов и складская порция выделяются вместе. Буксир после входа освобождается. Краны не удерживаются в ожидании склада.

Дополнительно нельзя удерживать причал, ожидая груз, который должно привезти другое судно. Поэтому ожидающее склад судно освобождает причал.

Отсутствие подходящих ресурсов вообще, запрещённый тип груза или отключённый необходимый подвоз/вывоз могут сделать конфигурацию невыполнимой. Тогда моделирование заканчивается по времени или сигналу пользователя.

## Как устроена сетевая версия

| Программа | Где находится состояние и что выводится |
|---|---|
| port_server | Сервер-диспетчер: владеет Port, назначениями, заданиями и последними подтверждёнными состояниями участников. Печатает собственные решения и принятые результаты, ведёт журнал. |
| port_dispatcher, port_sim | Сохранённые имена запуска того же сервера; дополнительных серверов не создают. |
| port_ship, port_tug, port_berth, port_crane, port_warehouse | Независимые TCP-клиенты по ролям. Получают только собственные команды, проверяют их, выполняют операцию и отвечают. Печатают свой индекс, действие, судно, объём и номер задания. |
| port_observer | Отдельный TCP-клиент общей панели. Получает целостные снимки: время, все ресурсы, склад, суда, последние события и состояние подключения. |

Данные модели изменяет только сервер. Рабочий клиент не получает указатели Port и не читает чужую память. 

В сервере один поток и цикл poll для всех сокетов. Разные рабочие клиенты - независимые процессы, их операции могут выполняться одновременно. Отправка команды не ожидает её немедленного ответа. Клиент во время задержки продолжает проверять свой сокет, поэтому может принять завершение от сервера. 

### Повторное подключение

При отключении рабочего клиента сервер сохраняет команду, последнее подтверждённое состояние роли, складские резервы и назначения. Модельное время приостанавливается, наблюдатели продолжают получать состояние ожидания, сервер продолжает принимать соединения. Нужно запустить ту же программу с теми же IP, портом и индексом: сервер восстановит состояние и повторит неподтверждённую операцию.

Запустите сервер как выше в терминале 1. Во втором терминале:

У склада показаны used/capacity и reserved, у судов - остаток, состояние и load/unload. Последние восемь событий показаны ниже. Перерисовывается только терминал наблюдателя; журнал не очищается.

### Выше 8: восстановление рабочих клиентов и общая остановка

Для проверки отключим кран во время разгрузки, затем запустим его повторно. Откройте четыре терминала в корне проекта.

**Терминал 1 - сервер:**

```bash
./port_server 127.0.0.1 5000 examples/manual.txt 1000 reconnect.log
```

Сервер напечатает READY и список пяти участников.

**Терминал 2 - наблюдатель:**

```bash
./port_observer 127.0.0.1 5000
```

До подключения участников панель показывает WAITING FOR WORKERS.

**Терминал 3 - участники, кроме крана:**

```bash
./port_ship 127.0.0.1 5000 0 &
./port_tug 127.0.0.1 5000 1 &
./port_berth 127.0.0.1 5000 2 &
./port_warehouse 127.0.0.1 5000 4 &

```

**Терминал 4 - кран:**

```bash
./port_crane 127.0.0.1 5000 3
```

После подключения крана начинается моделирование. Кран запущен без `&`, поэтому Ctrl+C в этом терминале остановит именно его.

#### Отключение во время операции

В терминале крана дождитесь строки:

```text
Worker 3: command=4 ship=0 volume=8 seq=... started
```

Здесь command=4 означает грузовую операцию. Сразу нажмите Ctrl+C, пока операция не завершилась.

Сервер должен вывести:

```text
Worker 3 disconnected; saved work retained
```

Наблюдатель:
```text
WAITING FOR RECONNECTION
```

Затем в другом терминале:

```bash
./port_crane 127.0.0.1 5000 3
```

Моделирование продолжится с сохранённым заданием, итог:

```text
departed=1 pending=0 cargo_operations=1 moved=8
```

Аналогично можно перезапустить судно, буксир, причал или склад с исходным индексом. Для автоматической демонстрации каждого случая используется make test.

### Аргументы, индексы и завершение

```text
port_server BIND_IP PORT CONFIG [DELAY_MS [LOG]]
port_ROLE SERVER_IP PORT ACTOR_INDEX
port_observer SERVER_IP PORT
```

PORT - 1..65535; DELAY_MS - 0..1000, по умолчанию 100; LOG - по умолчанию port.log. Первые 120 секунд сервер ждёт первичного подключения всех обязательных клиентов. Отмена первичного подключения сигналом возвращает код 3 и закрывает уже подключённых клиентов. При повторном подключении уже начатая модель ждёт клиента до его возврата или сигнала пользователя. Неизвестный конфиг и неверные аргументы отклоняются до запуска моделирования. --help показывает все формы запуска.

Порядок индексов: все суда, затем буксиры, причалы, краны и склад. ACTOR_INDEX и ID ресурса - разные значения. Сервер печатает точное соответствие для каждого конфига.

После обработки всех судов - `all ships processed`; по maxTime - `simulation time limit`; по SIGINT/SIGTERM - `Interrupted by user signal`. В двух последних случаях итог перечисляет ожидающие и частично обработанные суда. 

Коды выхода: 0 - штатный итог или завершение подключённого клиента; 2 - неверный ввод; 3 - ошибка подключения, запуска, протокола, вывода или модели. 

## Полный формат конфигурации

Файл содержит только десятичные целые числа и необязательное слово EXT. Числа разделяются любыми пробельными символами: одной строкой или по одному в строке. Комментарии, знаки перед числами, дроби и экспоненты не поддерживаются. Файл должен быть обычным текстовым файлом до 65535 байт, без нулевых байтов.

### Основные параметры

Первые девять чисел идут строго в таком порядке:

```text
maxTime tugCount berthCount craneCount warehouseCapacity enterExitTime cargoTime shipCount seed
```

| Позиция | Параметр | Допустимое значение |
|---|---|---|
| 1 | maxTime | 0..1000000 тиков; 0 - без ограничения времени |
| 2 | tugCount | 0..16 буксиров |
| 3 | berthCount | 0..16 причалов |
| 4 | craneCount | 0..16 кранов |
| 5 | warehouseCapacity | 1..1000000 единиц вместимости |
| 6 | enterExitTime | 1..10000 - базовая длительность входа/выхода |
| 7 | cargoTime | 1..10000 - базовая длительность грузовой порции |
| 8 | shipCount | 0..32 судна |
| 9 | seed | 0..1000000 - начальное состояние генератора задержек |

Для буксировки и грузовой порции длительность составляет base..base+base/5 включительно. Швартовка длится ровно moorTime. Seed воспроизводит последовательность генератора.

### Причалы

Далее идут **berthCount описаний причалов**, каждое из четырёх чисел:

```text
id small medium large
```

ID - 0..berthCount-1, без повторов. Последние три числа - 0 или 1: разрешены маленькие, средние и большие суда. Например, `0 1 1 0` - причал №0 принимает маленькие и средние суда.

### Краны

Затем craneCount описаний:

```text
id container liquid
```

ID - 0..craneCount-1, без повторов. Последние два числа - 0 или 1: совместимость с контейнерным и жидким грузом. Например, `0 1 0` - кран №0 обрабатывает только контейнерный груз.

### Суда

Затем shipCount описаний:

```text
shipType cargoType volume arrivalTime
```

- shipType: 0 - маленькое, 1 - среднее, 2 - большое судно.
- cargoType: 0 - контейнерный, 1 - жидкий груз.
- volume: 0..1000000 единиц требуемой обработки.
- arrivalTime: 0..1000000 тиков.

ID судов определяются порядком описаний, начиная с 0. При нулевом объёме грузовая стадия пропускается, но вход, причал и выход остаются.

Полный минимальный пример - содержимое manual.txt:

```text
100 1 1 1 10 2 3 1 7
0 1 1 1
0 1 1
0 0 8 0
```

Это 100 тиков, по одному ресурсу, склад на 10, буксировка 2 тика, грузовая порция 3 тика, одно маленькое судно с 8 единицами контейнерного груза в тик 0; seed=7.

### Значения без EXT

Если файл заканчивается после судов:

| Параметр | Значение по умолчанию |
|---|---|
| strategy | 1 - порядок по прибытию |
| reservation | 0 - по стадиям |
| moorTime | 1 тик |
| warehousePeriod | cargoTime |
| warehouseOut | capacity/4+1 за действие склада |
| cargoMask | 3 - оба типа груза |
| Начальные запасы | 0 для обоих типов |
| Подвоз | 0 для обоих типов |
| Маска каждого буксира | 7 - все типы судов |
| Производительность каждого крана | warehouseCapacity единиц за порцию |
| Операция каждого судна | 0 - разгрузка |
| Число кранов каждому судну | 1 |

### Расширение EXT

После судов укажите EXT и **все** следующие параметры. Частичное расширение не допускается.

Сначала десять чисел:

```text
EXT
strategy reservation moorTime warehousePeriod warehouseOut cargoMask initialContainer initialLiquid supplyContainer supplyLiquid
```

| Позиция после EXT | Параметр | Значение |
|---|---|---|
| 1 | strategy | 0 - ID; 1 - прибытие; 2 - меньший остаток |
| 2 | reservation | 0 - стадии; 1 - причал и входной буксир вместе |
| 3 | moorTime | 1..10000 тиков на швартовку/освобождение для ожидания |
| 4 | warehousePeriod | 1..10000 тиков между действиями склада |
| 5 | warehouseOut | 0..1000000 единиц максимального вывоза за действие |
| 6 | cargoMask | 1 - контейнеры; 2 - жидкость; 3 - оба |
| 7 | initialContainer | 0..1000000 контейнерного груза изначально |
| 8 | initialLiquid | 0..1000000 жидкого груза изначально |
| 9 | supplyContainer | 0..1000000 контейнерного груза максимального подвоза за действие |
| 10 | supplyLiquid | 0..1000000 жидкого груза максимального подвоза за действие |

Сумма начальных запасов не превышает warehouseCapacity. Нельзя задавать запас или подвоз типа, запрещённого cargoMask. При работе склад сначала вывозит готовый груз, затем подвозит в пределах свободной ёмкости; контейнерный тип рассматривается раньше жидкого. Ещё не завершённые разгрузки не вывозятся.

После этих десяти чисел:

1. **tugCount масок буксиров**, по одной каждому буксиру в порядке ID. Значение 0..7: бит 1 разрешает маленькие суда, 2 - средние, 4 - большие. Например, 5 означает маленькие и большие, 7 - все, 0 - никакие.
2. **craneCount производительностей**, по одной каждому крану в порядке ID: 1..1000000 единиц за одну грузовую порцию. Для набора кранов значения суммируются.
3. **shipCount пар** в порядке ID судов:

```text
operation cranesNeeded
```

operation: 0 - разгрузка, 1 - погрузка. cranesNeeded: 1..16. Нехватка совместимых кранов означает ожидание. Груз учитывается один раз за общую порцию после ответов всех кранов.

### Полный пример EXT с погрузкой двумя кранами

```text
300 2 2 2 40 2 4 2 42
0 1 1 1
1 1 1 1
0 1 1
1 1 1
0 0 35 0
2 1 20 0
EXT
1 1 2 5 0 3 10 0 10 10
1 4
5 5
1 2
1 2
```

- Два буксира, два причала, два крана, склад на 40 и два судна.
- Первое судно маленькое, ему нужно погрузить 35 единиц контейнеров; второе большое, ему нужно погрузить 20 единиц жидкости.
- strategy=1, reservation=1, швартовка 2 тика, склад действует каждые 5 тиков.
- Вывоза нет; склад принимает оба типа, изначально есть 10 контейнерных единиц, жидкости нет.
- Подвозится до 10 единиц каждого типа за действие, насколько позволяет свободное место.
- Первый буксир подходит только маленьким судам, второй - только большим.
- Производительность каждого крана - 5; каждому судну нужно по два крана.

### Некорректные и невыполнимые данные

Буквы вместо числа, знак, переполнение, повтор ID, неверная совместимость, обрезка EXT и бинарные байты отклоняются до запуска участников. Диагностика показывает путь, строку рядом с ошибкой и причину.

Корректный файл с нулём буксиров или несовместимым оборудованием допускается: недоступный ресурс не появляется автоматически. Такой сценарий фиксирует ожидание по времени или прерывается пользователем. При maxTime=0 он может ждать сигнала.

### Что демонстрирует каждый файл examples

| Файл | Для чего нужен |
|---|---|
| `manual.txt` | Простой полный цикл; запуск клиентов и наблюдателей |
| `loading_multi.txt` | Погрузка несколькими кранами и резервирование |
| `warehouse_wait.txt` | Ожидание места на складе и продолжение разгрузки |
| `loading_partial_reserved.txt` | Частичная погрузка: освобождение причала и продолжение |
| `unloading_dependency.txt` | Погрузчик освобождает склад для разгрузчика |
| `time_limit.txt` | Завершение по времени с незавершёнными судами |
| `zero_ships.txt` | Корректное завершение без судов |
| `unlimited_blocked.txt` | Неограниченный режим до Ctrl+C |


## Проверки и фактические результаты

```bash
make test
```

Проверка памяти:

```bash
make sanitize
ASAN_OPTIONS=detect_leaks=1:halt_on_error=1:quarantine_size_mb=16 UBSAN_OPTIONS=halt_on_error=1 ./port_tests
make clean
make
```

| Сценарий | Фактический результат |
|---|---|
| manual.txt | T=8, arrived=1, departed=1, pending=0, cargo_operations=1, moved=8 |
| loading_multi.txt | T=30, departed=2, pending=0, cargo_operations=6, moved=55 |
| warehouse_wait.txt | T=151, departed=2, pending=0, cargo_operations=37, moved=75 |
| loading_partial_reserved.txt | T=11, departed=2, pending=0, cargo_operations=3, moved=15 |
| unloading_dependency.txt | T=11, departed=2, pending=0, cargo_operations=3, moved=15 |
| time_limit.txt | T=9, arrived=2, departed=0, pending=3, partial=1, moved=5; третье судно ещё не прибыло |
| zero_ships.txt | T=0, arrived=0, departed=0, pending=0 |
| Три наблюдателя | Один отключён и подключён повторно, третий подключён после начала разгрузки; все получили итог и завершились |
| Повторный запуск каждой из пяти ролей | После отключения и восстановления каждой роли итог manual.txt остался cargo_operations=1, moved=8 |
| SIGINT серверу во время входа | T=1, pending=1, moved=0; сервер, активные рабочие клиенты и наблюдатель завершились |
| Дубль, неверная роль, чрезмерная длина кадра | Ошибочный клиент отклонён, сервер продолжил и завершил manual.txt |
| Неправильный ввод и границы TCP-чтений | Неверный порт/конфиг отклонены; по одному байту и два кадра вместе разобраны корректно |

Один наблюдатель предоставляет общую панель для уровня 6-7. Одновременная работа трёх наблюдателей с повторным подключением подтверждает расширение на 8 баллов. Восстановление пяти рабочих ролей и завершение всех клиентов вместе с сервером подтверждают дополнительные возможности уровня выше 8.

Пример реального итогового вывода сервера для manual.txt:

```text
[T=000008] Termination: all ships processed
[T=000008] FINAL arrived=1 departed=1 pending=0 partial=0 cargo_operations=1 moved=8 wait=0 max_queue=0
[T=000008] Проверка ограничений ресурсов: пройдена
```
