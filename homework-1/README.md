
# ИДЗ1, вариант 42: Морской грузовой порт

Дискретно-событийная модель работы морского порта на языке C. Программа симулирует жизненный цикл судов: прибытие, швартовку, разгрузку кранами на склад и отбытие.


### Выполнила

Бусыгина Ксения Сергеевна, БПИ253


## Особенности реализации

- Очередь событий с сортировкой по времени.
- Ресурсы: буксиры, причалы, краны и склад с ограниченной вместимостью
- Причалы и краны имеют настройки совместимости с типами судов и грузов
- Если склад переполнен, то судно разгружает доступный остаток и уплывает

## Сценарий работы

В основе симуляции лежит дискретная модель: время движется не непрерывно, а скачками от одного события к следующему. Все взаимодействия между сущностями описываются через события, которые хранятся в очереди (отсортированы по времени наступления).

### Сущности и их роли

- **`Ship`** — 9 состояний: `NOT_ARRIVED` → `QUEUED` → `ENTERING` → `WAITING_BERTH` → `WAITING_CRANE_AND_WAREHOUSE` → `UNLOADING` → `WAITING_DEPART` → `EXITING` → `DEPARTED`
- **`Tug`** — ограниченный ресурс для входа/выхода судна
- **`Berth`** — ограниченный ресурс с совместимостью по типу судна (`SMALL`/`MEDIUM`/`LARGE`)
- **`Crane`** — ограниченный ресурс с совместимостью по типу груза (`CONTAINER`/`LIQUID`)
- **`Warehouse`** — ограниченный ресурс с фиксированной вместимостью
- **`Dispatcher`** — принимает решения о назначении ресурсов судам
- **`EventQueue`** — очередь событий, отсортированная по времени
- **`Port`** — агрегатор всех сущностей

### Жизненный цикл судна

```text
[Судно прибывает]
       │
       ▼
  Событие ARRIVE ──► Судно переходит в QUEUED
       │
       ▼
  Диспетчер ищет свободный буксир (tryEnter)
       │
       ├─ нет буксира ─► Судно ждёт в очереди
       │
       └─ буксир найден ──► Судно → ENTERING
                              │
                              ▼
                     Событие ENTER_DONE
                              │
                              ▼
                     Буксир освобождается, судно → WAITING_BERTH
                              │
                              ▼
                     Диспетчер ищет совместимый причал (tryBerth)
                              │
                              ├─ нет причала ─► Судно ждёт
                              │
                              └─ причал найден ──► Судно → WAITING_CRANE_AND_WAREHOUSE
                                                        │
                                                        ▼
                                               Диспетчер ищет кран + место на складе (tryUnload)
                                                        │
                                              ┌─────────┼────────────┐
                                              ▼         ▼            ▼
                                         нет крана  склад полон     успех
                                              │         │              │
                                              ▼         ▼              ▼
                                           ждёт    → WAITING_DEPART  → UNLOADING
                                                   (судно уплывает    │
                                                    с остатком)       ▼
                                                             Событие UNLOAD_DONE
                                                                      │
                                                                      ▼
                                                             Кран освобождается,
                                                             судно → WAITING_DEPART
                                                                      │
                                                                      ▼
                                                             Диспетчер ищет буксир (tryDepart)
                                                                      │
                                                                      ▼
                                                             Судно → EXITING → Событие EXIT_DONE
                                                                      │
                                                                      ▼
                                                                 Буксир освобождается,
                                                                 причал освобождается,
                                                                 судно → DEPARTED

```

### Ключевые особенности взаимодействия
1. Кран и место на складе резервируются одновременно. Если кран свободен, а склад полон, кран сразу освобождается, а судно отправляется на отбытие
2. Если на складе меньше места, чем груза на судне, разгружается только доступный остаток. Судно уплывает с частью груза
3. Случайные задержки: время входа/выхода и разгрузки варьируется в пределах 0-20% от базового значения (функция randomDelay)
4. Все случайные числа генерируются из одного значения параметра seed, указанного в конфиге. Одинаковый seed + одинаковый конфиг = идентичный результат

## Пользовательский интерфейс

Программа предоставляет два канала вывода информации: консольный дашборд (в реальном времени) и лог-файл

### Консольный дашборд
Дашборд перерисовывается на каждом тике симуляции и отображает текущее состояние порта в виде текстовой таблицы:
```
+---------------- ARKHANGELSK BAKARITSA PORT ----------------+
| Time: 5    / 25                                            |
+------------------------ RESOURCES -------------------------+
| Tugs (3):   [ 0*] [ 1 ] [ 2 ] 
| Berths (2): [ 0#] [ 1 ] 
| Cranes (2): [ 0^] [ 1 ] 
| Warehouse: 30 / 100
+--------------------------- SHIPS --------------------------+
| #0 type=1 cargo=0 volume=30    | entering                  |
| #1 type=2 cargo=1 volume=50    | not arrived               |
| #2 type=1 cargo=0 volume=40    | queued                    |
| #3 type=0 cargo=1 volume=60    | not arrived               |
+------------------------------------------------------------+
```

#### Обозначения ресурсов:
- `[ 0*]` — буксир #0 занят (*), `[ 0 ]` — свободен
- `[ 0#]` — причал #0 занят судном (#), `[ 0 ]` — свободен
- `[ 0^]` — кран #0 работает (^), `[ 0 ]` — свободен
- Warehouse: 30 / 100 — использовано 30 из 100 единиц вместимости

#### Статусы судов:
- `not arrived` — судно ещё не прибыло (время прибытия не наступило)
- `queued` — судно прибыло и ждёт буксир для входа
- `entering` — судно заходит в порт с буксиром
- `waiting berth` — судно ждёт свободный причал
- `waiting crane/warehouse` — судно ждёт кран и место на складе
- `unloading` — идёт разгрузка
- `waiting depart` — судно разгружено, ждёт буксир для выхода
- `exiting` — судно выходит из порта
- `departed` — судно покинуло порт

Дашборд обновляется с задержкой, заданной вторым аргументом запуска (по умолчанию 1000 мс). При запуске с задержкой 0 дашборд выводится мгновенно

### Лог-файл `port.log`
Все действия симуляции записываются в файл `port.log` в хронологическом порядке:

```
=== Simulation Start ===
Resources: tugs=3, berths=2, cranes=2, warehouse=100
Seed: 100
[T=0000] Ship #0 arrived (type=1, cargo=0, vol=30)
[T=0000] Ship #0: tug #0 entering
[T=0001] Ship #1 arrived (type=2, cargo=1, vol=50)
...
[T=0012] Ship #3: tug #0 exiting

========== FINAL STATISTICS ==========
Ships arrived:              4
Ships departed:             4
Ships pending:              0
Unloaded:                   1
Total wait time:            10 ticks
Max queue length:           2
========================================
=== Simulation Finished ===
```
Лог содержит:
- Параметры запуска (ресурсы, seed для генератора случайных чисел)
- Полную хронологию событий с метками времени [T=XXXX]
- Итоговую статистику: количество прибывших/отбывших судов, время ожидания, максимальную длину очереди, число неразгруженных судов
## Завершение программы

Симуляция может завершиться по одному из трёх сценариев:
1. Штатное завершение (все суда обслужены)
Программа завершается автоматически, когда выполнены оба условия:
- Все суда находятся в состоянии `DEPARTED` (успешно отбыли)
- Очередь событий пуста

В логе появляется запись:
```
=== Simulation Finished ===
```

*Пример*: при `maxTime = 25` и 4 судах, если все суда успевают пройти полный цикл до T=25, симуляция завершится досрочно (например, на T=16), не дожидаясь конца отведённого времени

2. Завершение по исчерпанию времени (maxTime)

Если к моменту `currentTime > maxTime` остаются суда в активных состояниях (QUEUED, WAITING_BERTH, UNLOADING и т.д.), симуляция принудительно завершается. Это моделирует ситуацию, когда порт не успевает обслужить все суда за отведённое время. В статистике такие суда будут учтены как `shipsPending` (остающиеся в порту)

*Пример*: если в конфиге `maxTime = 10`, а последнее судно прибывает на T=8 и ему нужно 5 тиков на обслуживание, оно не успеет уплыть, и симуляция завершится на T=10 с `shipsPending > 0`

3. Прерывание пользователем (Ctrl+C)

Пользователь может в любой момент прервать симуляцию комбинацией `Ctrl+C`. Программа обрабатывает сигнал `SIGINT` через обработчик `onSigint`, который устанавливает флаг `interrupted = true`.
Главный цикл симуляции проверяет этот флаг на каждом тике и корректно завершает работу:
- Освобождаются все ресурсы (память, файловые дескрипторы)
- В лог записывается итоговая статистика на момент прерывания
- В лог добавляется пометка:
```
  ! Interrupted by user (Ctrl+C) !
```
