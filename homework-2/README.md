## Сценарий работы

| Сущность | Поток | Что делает |
|---|---|---|
| Судно (`Ship`) | `shipThread`, по одному на судно | ждёт своё время прибытия, затем по очереди запрашивает у диспетчера: буксир для входа, причал, кран и место на складе, буксир для выхода |
| Диспетчер (`Dispatcher`) | `dispatcherThread`, один на программу | спит на семафоре, по пробуждению обходит суда и назначает ресурсы по стадиям (`tryEnter`, `tryBerth`, `tryUnload`, `tryDepart`) |
| Буксир (`Tug`) | `tugThread`, по одному на буксир | ждёт назначенное судно, буксирует его, освобождается |
| Кран (`Crane`) | `craneThread`, по одному на кран | ждёт назначенное судно, разгружает одну порцию груза, освобождается |
| Склад (`Warehouse`) | `warehouseThread`, один на программу | периодически вывозит груз (каждые `unload_time` тиков освобождает 1/4 вместимости), что позволяет продолжить приостановленную разгрузку |
| Причал (`Berth`) | не поток | пассивный ресурс (занят/свободен), которым управляет диспетчер под мьютексом |
| Главный поток | `main` | время симуляции (тик = `delay` мс), отрисовка дашборда, остановка потоков |

### Жизненный цикл судна

`NOT_ARRIVED` → `QUEUED` → `ENTERING` → `WAITING_BERTH` → `MOORED` → (`WAITING_CRANE_AND_WAREHOUSE` → `UNLOADING`) * кол-во раз, необходимых для полной разгрузки → `WAITING_DEPART` → `EXITING` → `DEPARTED`

Если склад полон, судно остаётся на причале в `WAITING_CRANE_AND_WAREHOUSE` (разгрузка приостановлена) и продолжает, когда склад освободится (замена поведению из ИДЗ1, где судно уплывало с остатком)

### Синхронизация

- `port->mutex` защищает всё общее состояние: состояния судов, ресурсы, статистику, время, журнал событий
- Семафоры `Sema` (`sem_t`, в `sync.c`):
  - `disp.wake` будит диспетчера (на него могут повлиять суда, буксиры, краны и склад)
  - `ship->granted` будит судно, когда запрошенный этап выполнен
  - `tug->start` и `crane->start` выдают буксиру и крану судно
- Тик симуляции продвигает главный поток; остальные потоки ждут нужный тик (`simWait`)
- Остановка: главный поток ставит `stop` и делает `semaPost` на всех семафорах, чтобы разбудить спящие потоки.

### Исключение взаимной блокировки

Ресурсы назначаются по стадиям. Буксир освобождается сразу после входа или выхода, кран и место на складе резервируются одновременно, а если места нет, кран сразу отдаётся обратно. Судно, которое держит причал и ждёт склад, не держит ни буксир, ни кран, а склад освобождается независимо от судов. Поэтому deadlock не возникает

### Переход в директорию

```bash
  cd homework-2
```
### Запуск

```bash
make clean && make              # синхронизация семафорами sem_t (по умолчанию)
make clean && make SYNC=cond    # ИЛИ вторая программа: мьютекс + условная переменная
make run                        # config.txt, тик = 1000 мс
./port_sim <конфиг> <мс на тик>
```

- `SYNC=cond` добавляет флаг компиляции `-DCOND`: вместо семафоров `Sema` строится из мьютекса и условной переменной (`sync.c`)
- При смене `SYNC` нужен `make clean`
- Задержка меньше 1 мс заменяется на 1 мс
- Формат конфигурационного файла не изменился по сравнению с ИДЗ1. `max_time = 0` означает неограниченное время.

### Консольный дашборд
Дашборд перерисовывается на каждом тике симуляции и отображает текущее состояние порта в виде текстовой таблицы:
```

| Time: 21   / 25                                            |
+------------------------ RESOURCES -------------------------+
| Tugs (3):   [ 0 ] [ 1 ] [ 2 ] 
| Berths (2): [ 0#] [ 1 ] 
| Cranes (2): [ 0^] [ 1 ] 
| Warehouse: 50 / 100
+--------------------------- SHIPS --------------------------+
| #0 type=1 cargo=0 volume=0     | departed                  |
| #1 type=2 cargo=1 volume=0     | departed                  |
| #2 type=1 cargo=0 volume=0     | departed                  |
| #3 type=0 cargo=1 volume=2     | unloading                 |
+-------------------------- EVENTS --------------------------+
| [T=0016] Warehouse: 26 units shipped out (warehouse 74/100)
| [T=0016] Crane #0: unloading of ship #3 in progress
| [T=0018] Crane #0 released: ship #3 portion unloaded, 2 left on board
| [T=0018] Ship #3 requests crane and warehouse space
| [T=0018] Ship #3: crane #0 assigned, portion 2 of 2, warehouse 76/100
| [T=0018] Crane #0: unloading of ship #3 started (portion 2)
| [T=0020] Crane #0: unloading of ship #3 in progress
| [T=0020] Warehouse: 26 units shipped out (warehouse 50/100)
+------------------------------------------------------------+
```

#### Обозначения ресурсов:
- `[ 0*]` — буксир #0 занят (*), `[ 0 ]` — свободен
- `[ 0#]` — причал #0 занят судном (#), `[ 0 ]` — свободен
- `[ 0^]` — кран #0 работает (^), `[ 0 ]` — свободен
- Warehouse: 30 / 100 — использовано 30 из 100 единиц вместимости

Дашборд перерисовывается каждый тик и (по сравнению с ИДЗ1) дополнен разделом EVENTS с несколькими последними событиями симуляции. Все события пишутся с метками [T=XXXX], в конце выводится итоговая статистика.

## Завершение программы

Симуляция может завершиться по одному из трёх сценариев:
1. Штатное завершение (все суда обслужены)

В логе появляется запись:
```
=== Simulation Finished ===
```

*Пример*: при `maxTime = 25` и 4 судах, если все суда успевают пройти полный цикл до T=25, симуляция завершится досрочно (например, на T=24), не дожидаясь конца отведённого времени

2. Завершение по исчерпанию времени (maxTime)

Если к моменту `currentTime > maxTime` остаются суда в активных состояниях, симуляция принудительно завершается. Это моделирует ситуацию, когда порт не успевает обслужить все суда за отведённое время. В логе перечислены не завершённые суда (not finished), в статистике фиксируется число ожидающих и частично выгруженных.

*Пример*: если в конфиге `maxTime = 10`, а последнее судно прибывает на T=9 и ему нужно время на обслуживание, оно не успеет уплыть, и симуляция завершится на T=10

3. Прерывание пользователем (Ctrl+C)

Пользователь может в любой момент прервать симуляцию комбинацией `Ctrl+C`. Программа обрабатывает сигнал `SIGINT` через обработчик `onSigint`, который устанавливает флаг `interrupted = true`.
Главный цикл симуляции проверяет этот флаг на каждом тике и корректно завершает работу:
- Освобождаются все ресурсы (память, файловые дескрипторы)
- В лог записывается итоговая статистика на момент прерывания
- В лог добавляется пометка:
```
  ! Interrupted by user (Ctrl+C) !
```

При `max_time` = 0 это единственный способ остановить программу, если какое-то судно не может быть обслужено

## Тесты

```bash
make test                # семафоры
make test SYNC=cond      # условные переменные
```

Проверяются: сборка, штатное завершение, приостановка и продолжение разгрузки при маленьком складе, завершение по времени, прерывание по SIGINT

Порядок событий внутри одного тика зависит от ОС, поэтому логи двух запусков могут отличаться порядком строк, в связи с чем тест совпадания логов реализован не был
